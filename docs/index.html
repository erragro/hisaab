01

The problem

A dispute does not happen in one message.

A platform worker may be locked out of an app after a complaint, lose an incentive, or find a payout short. The proof is scattered: an in-app alert, an earnings screen, a support chat, a bank entry, a memory of a date.

Then the clock starts. A person needs to understand what happened, save what they have, decide their next move, and write to the right place—without losing track of a deadline.

Hisaab is the worker-side record. It does not decide a dispute. It helps a worker organise their own facts and take the next practical step.

01

Private by default

Every API request verifies a Firebase ID token. User data is scoped on the server; direct Firestore client access is denied.

02

Evidence has a history

Each uploaded item commits to its file hash, capture time, and preceding hash. The resulting record can be exported as a manifest.

03

Important math is deterministic

Deadlines, working-day calculations, lost-wage estimates, and draft readiness are computed by tested Python code, not a language model.

04

Build story

An honest build record

Started in AI Studio.
Operated on Cloud Run.

Hisaab’s product direction, custom security instructions, and original interactive prototype were created in Google AI Studio. The public Hisaab service is a separately engineered Cloud Run application. This page distinguishes the prototype, its AI Studio credential, and the deployed production service rather than representing them as the same codebase.

01

GOOGLE AI STUDIO

Security instructions set the foundation

Custom instructions established the intended guardrails: Firebase identity, server-side verification, user isolation, Secret Manager, safe AI output, and deterministic decisions for high-impact calculations.

02

AI STUDIO PROTOTYPE

The first Hisaab experience

AI Studio produced the original Hisaab prototype and its case-journal experience. Its published URL is retained as a public prototype and as evidence of the AI Studio build process.

03

VERIFICATION

Test the integration boundaries

The exported prototype was reviewed separately from the deployed service. Its Gemini Developer API key was verified with a live model request before being placed server-side in the Cloud Run service.

04

CLOUD RUN

A distinct, public production service

The live service uses the public GitHub codebase: Firebase Authentication, server-scoped Firestore access, Gemini through a server backend, and keys injected from Secret Manager.

What is live today

A Gemini Developer API key created through AI Studio was tested and added to Cloud Run through Secret Manager. The exported AI Studio React/Express package has not been represented as the Cloud Run source; the production service is the separately maintained public repository.
